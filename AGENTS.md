# PLAYER TWO — инструкции проекта

## Цель и ограничения
- Основной продукт — простая Web First игра на Godot 4.6 / GDScript: чиби Эмиль и Света, автоматические прыжки по цветным платформам. Русский интерфейс, лёгкая мультяшная графика. Не возвращать стиль PS2.
- Каждая новая игровая система должна работать в Godot 4 Web Export. Основная цель — браузер; нативный запуск служит вспомогательной проверкой.
- Использовать Compatibility / WebGL 2 и однопоточный экспорт. Не добавлять обязательные Thread, C#/.NET, нативные расширения, процессы ОС или платформенные API без рабочей Web реализации. Проверять поддержку новых зависимостей до внедрения.
- Игровые ресурсы — res://; сохранения при необходимости — user:// с учётом браузерного хранилища и недоступности сохранения. Не обращаться к путям Windows из игрового кода. Инструменты сборки могут быть платформенными.
- Звук, fullscreen и прочие browser APIs учитывать с ограничениями браузера; для нужных разрешений использовать действие пользователя. Поддерживать клавиатуру и сенсорное управление.
- Все ресурсы локальные. Без CDN, аналитики, облачных API, регистрации. Локальный сервер слушает только 127.0.0.1. Не публиковать игру и не создавать туннели без явного запроса.
- Исходные модели не изменять. Рабочие облегчённые копии сохраняют материалы, WebP и UV. Не усложнять MVP без задачи пользователя.

## Где работать
| Задача | Файлы |
| --- | --- |
| Меню, состояния, ввод, камера, игровой цикл | game/scripts/main.gd |
| Прыжок, расстояния и генерация маршрута | game/scripts/jump_rules.gd |
| Блинчики, камень, трещины и разрушение | game/scripts/jump_platform.gd |
| Загрузка и кэш персонажей | game/scripts/characters.gd |
| Модели игры | game/assets/models/*-lite.glb |
| Вход и настройки | game/main.tscn, game/project.godot |
| Web экспорт и его текущие ограничения | game/export_presets.cfg, game/WEB.md |
| Тест маршрутов и камня | game/tests/platform_rules_test.gd |
| Результаты выполненных проверок | game/ПРОВЕРКА.md |

dist/ и server.mjs — прежний Three.js просмотрщик, НЕ Web сборка Godot. Не менять его при задачах игры. game/source-models/ — архив исходников. optimize-chibi.mjs — инструмент подготовки моделей; не запускать без необходимости.

## Текущее состояние
- mvp-v0.2.0: случайные промежутки 1,8–2,2; соседние платформы смещаются по горизонтали, у трёх подряд нет общей линии приземления. Камень трескается после первого приземления, ломается после второго, сохраняя второй отскок.
- Управление A/D или стрелки, прыжок автоматический; Esc — пауза, R после падения — повтор. Лучший результат пока только на время сессии.
- Web Export впервые собран и проверен в браузере на компьютере: модели, ввод, прыжки, пауза, падение и повтор. Портретная компоновка пока с чёрными полями; физический телефон и разрушение камня в браузере не проверены. Подробности: game/WEB.md.

## Экономный порядок работы
1. Начинать с этих инструкций и git status --short. Читать только нужные строки файлов по таблице и относящиеся к задаче изменения.
2. Не перечитывать весь репозиторий, историю чата, все README и старые отчёты для небольшой правки. Расширять поиск только при конкретной зависимости или ошибке.
3. Посторонние документы и их вспомогательные файлы не читать, не учитывать и не добавлять в Git. Игнорируемые каталоги, кэши, модели и бинарники не сканировать без необходимости задачи.
4. Делать минимальное законченное изменение. Без несвязанного рефакторинга, новых систем и повторной оптимизации моделей. Не привлекать субагентов без запроса.
5. Запускать проверки по изменению, не весь набор для правки текста. После успешной проверки не повторять её без причины. Для новой игровой системы нужен экспорт и проверка в браузере; если среда мешает — явно записать, что не проверено.
6. При изменении архитектуры, команд или статуса Web обновить соответствующую краткую документацию. AGENTS.md хранит правила и карту, а не журнал каждой задачи.

## Команды и версии
Команды из корня, PowerShell. Локальный движок: `.tools/godot/Godot_v4.6-stable_win64_console.exe` (ниже GODOT).
- Физика/генерация/камень: `& GODOT --headless --path game --script res://tests/platform_rules_test.gd` — 40 000 переходов.
- Интеграция/модели/UI: `& GODOT --path game -- --self-test` — реальный игровой прогон, снимки в qa/. Не запускать headless для проверки внешнего вида.
- Ручной нативный запуск: `Играть.cmd`; редактор: `Открыть проект Godot.cmd`.
- Браузерный запуск готовой сборки: `Играть в браузере.cmd` → start-web-game.ps1 → server-game.mjs, только http://127.0.0.1:4174/ . Сборка лежит в build/web/; после изменения исходников её нужно пересобрать.
- Web: команды и проверка в game/WEB.md. Снимки и результаты сборки не коммитить.
- Приватный репозиторий: https://github.com/mimicode666/player-two-chibi-jump ; GLB/PNG/WebP в Git LFS. Инструменты .tools/ и кэши не входят в Git.
- Перед сохранением проверять diff и добавлять конкретные файлы задачи. Не менять чужие правки. В финале кратко: результат, проверка и существенные ограничения.
