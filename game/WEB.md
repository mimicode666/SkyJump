# Web First

Браузер — основная целевая платформа игры. Godot 4.6, GDScript, Compatibility / WebGL 2, однопоточный Web Export без нативных расширений. Эти настройки соответствуют [документации Godot 4.6](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_web.html).

## Текущий статус

Preset `Web` в `export_presets.cfg` собран официальными шаблонами 4.6.stable и запущен во встроенном браузере Codex на компьютере. В составе семь актуальных моделей; новый Кирби и Синнаморол используют встроенное моргание. Есть цены, покупки, локальные рекорды, продолжение и бонус ×2 на 10 минут. Проверки и ограничения — в `ПРОВЕРКА.md`.

Первый этап SDK Яндекс Игр реализован через JavaScriptBridge: готовность, игровой статус, пауза/фокус, rewarded-реклама. Локальная игра SDK не загружает; ошибки SDK не блокируют игру. Настоящий показ рекламы ещё не проверен — черновика нет. Архив и следующий этап описаны в `YANDEX.md`; `build-yandex.ps1` только создаёт локальный ZIP. Общего лидерборда и облачных сохранений пока нет.

Web-профиль зеркалируется в localStorage синхронно после изменений, чтобы немедленная перезагрузка не опережала сохранение Godot в IndexedDB. При блокировке localStorage используется user://; при недоступности обоих хранилищ прогресс временный. QA-пути отделены от игрового кошелька.

Профиль v4 возвращает стоимость снятых платных карт один раз (50/75/100/150 монет), сохраняя скины, баланс, рекорды и бонус ×2. Версия миграции и возврат записываются совместно, в том числе в localStorage. Отдельных карт больше нет: все зоны доступны в одном подъёме. На ПК половины экрана принимают удержание мыши; синтетические события мыши от касаний игнорируются. Платформы непрозрачны: визуальная модель смещена вдоль оси ортографической камеры вперёд, логическая физика остаётся на прежней плоскости.

`Играть в браузере.cmd` запускает скрытый локальный Node.js сервер и открывает http://127.0.0.1:4174/ . Повторный запуск использует уже работающий сервер. `Играть.cmd` запускает нативную игру. Старый просмотрщик удалён из текущего дерева проекта.

SkyJump использует адаптивную портретную и альбомную компоновку без чёрных полей. Монетка с балансом находится поверх меню, включая список персонажей. Портретная ширина камеры — 8,8. Нижний край обзора на игровой плоскости закреплён на 2 единицы выше прежнего порога падения (`camera_height − 7`): к проигрышу герой уже целиком за экраном, нижние недоступные платформы не видны. Наклон камеры учтён, дополнительное Y-сглаживание в игре убрано, чтобы не появлялоcь отставание от порога. Масштаб, физика, генерация, боковые границы, разрешение и сглаживание 3D прежние. Линии падения нет.

Путешествие следует максимальной высоте: земля → дождь (180 м) → над облаками (400 м) → закат (700 м) → ночь (1100 м) → Луна (1600 м) → галактики (2300 м). Каждый переход занимает 120 м; падение не перематывает окружение назад, повтор начинает с земли. Декорации и небольшие покрытия платформ полностью локальные: меши, MultiMesh и кэшированные 64×64 текстуры. Физика, маршрут и его RNG не меняются. На специальных платформах сохраняются сигнальные цвета/знаки.

При приземлении анимируется дочерний визуал платформы, не её позиция столкновения: упругий диск и кольцо, крошки камня, распрямление пружины. Фигурка не сжимается. Три оригинальных WAV (0,12–0,20 с, mono PCM) загружаются из res://assets/audio; генератор исходников — generate-bounce-audio.ps1. Используется обычный AudioStreamPlayer и стандартный Web Sample, без потоковой генерации и AudioEffects ([ограничения Godot Web Audio](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_web.html#audio-playback)). Воспроизведение разрешается после кнопки старта, выключатель в меню сохраняется в профиле. Пауза, реклама и потеря фокуса останавливают звук.

Сенсорные зоны занимают левую и правую половины всего игрового экрана независимо от его размера; видимые стрелки убраны. Касание, начатое на паузе, не управляет героем. Ввод сбрасывается при паузе, смене размера и потере фокуса. Перед первым стартом за открытие показывается локальная векторная заставка с управлением касаниями и клавиатурой; до подтверждения физика и GameplayAPI не запускаются. Список персонажей в портрете увеличен за счёт меньшего превью, баланс в меню крупнее, экран рекорда содержит один лучший результат и локальное место №1.

Debug Web-сборка с assertions проверяет все модели, моргание Кирби, видимость кошелька, однократный подбор монет и сохранение, специальные платформы, паузу, переход через края и мультитач. Последний маршрут: 54 приземления, высота 170,54 игровых единицы, 20 платформ. QA-баланс восстановился после реальной перезагрузки страницы.

Физический телефон, Safari/Firefox и отключение интернета не проверены. События касаний проверены внутри Web-движка, это не замена испытанию на устройстве. Текущая release-сборка без сжатия занимает около 80,41 МБ; производительность на слабых устройствах и громкость/задержка звука на реальных устройствах не измерены. Снятые персонажи исключены из игровых ресурсов, оригиналы остаются в архиве.

## Подготовка локальной сборки

Понадобятся официальные Export Templates **4.6.stable**, соответствующие установленному движку (Editor → Manage Export Templates). После первоначальной установки сборка не должна требовать интернет. Шаблоны не хранить в Git.

Из корня репозитория, PowerShell:

```powershell
New-Item -ItemType Directory -Force build/web | Out-Null
& '.tools/godot/Godot_v4.6-stable_win64_console.exe' --headless --path game --export-release Web ../build/web/index.html
```

Результат — папка `build/web/`, исключённая из Git. Не переименовывать отдельные файлы экспорта. Для браузера требуется HTTP, не открытие index.html через file://. Сервер `server-game.mjs` обслуживает только build/web на 127.0.0.1:4174 и отдаёт `.wasm` как `application/wasm`. Запуск без открытия вкладки: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./start-web-game.ps1 -NoBrowser`. Журналы — .local/web-game*.log. Публикация не разрешена.

## Проверка при добавлении системы

Для быстрой проверки камеры есть `--camera-test` (те же правила debug Web args, что ниже). Проверяет пять соотношений сторон, один GLB, уход за край до смерти, прежние горизонтальные границы, падение, повтор и паузу. Использует отдельный `qa-camera-wallet.cfg`, не игровой профиль.

`--journey-test` проверяет миграцию/однократный возврат, семь зон и непрерывность цвета, независимость RNG, текстуры, непрозрачность тел платформ, визуальный отскок/пружину/крошки, реальные два приземления на камень и усиленный отскок, паузу, сброс окружения и PCM-ресурсы. Один Пикачу, отдельный qa-journey-wallet.cfg. Дополнительный `--journey-tour` в debug даёт кнопку перелистывания зон для Web-снимков; обычная сборка запускается без этих аргументов.

1. Собрать Web без ошибок; открыть через локальный HTTP в браузере с WebGL 2.
2. Проверить затронутые модели и текстуры, начало игры, управление, камень, падение, повтор, паузу и возврат в меню; проверить изменённую систему отдельно. Для сохранений проверить баланс после перезагрузки страницы.
3. Проверить изменение размера окна, узкий экран, сенсорный ввод и возврат фокуса. Эмуляцию не выдавать за тест на физическом телефоне.
4. Проверить ошибки браузера, отсутствие внешних запросов и продолжение работы при отключённом интернете, пока локальный сервер работает.
5. Записать браузер, результат и ограничения в `ПРОВЕРКА.md`; обновить статус здесь и в AGENTS.md после первого успешного прогона.

## Ограничения архитектуры

Не использовать desktop-only API в обязательном игровом пути. Для платформенных функций нужен Web вариант с тем же поведением или явно допустимой деградацией. Сохранения в user:// зависят от доступности браузерного хранилища; отказ не должен ломать игру. Звук и fullscreen запускать после пользовательского действия. Не добавлять обязательные потоки или SharedArrayBuffer; для текущего однопоточного preset они не нужны.

Самопроверка `--self-test` поддерживает native и Web: только нативный запуск сохраняет снимки в qa/ и завершает процесс. В Web она возвращается в меню. Для браузерной проверки экспортировать **debug** Web в build/web/check.html, заменить `"args":[]` на `"args":["--","--self-test"]` в полученном check.html и открыть его на локальном сервере. Успех — `SKYJUMP_MECHANICS_OK`, `SKYJUMP_MODEL_UI_OK`, `SKYJUMP_CURRENCY_OK`, `STONE_PHYSICS_OK`, `MVP_SELF_TEST_OK` в консоли **без ошибок assertions**. Размер viewport задавать до перезагрузки теста: смена размера намеренно сбрасывает касания. QA использует отдельный кошелёк `qa-run-wallet.cfg`; после перезагрузки `QA_WALLET_LOADED` должен совпадать с последним `QA_WALLET_SAVED`. Тестовая страница и её файлы остаются в игнорируемой build/. Бюджет производительности оценивать в браузере, а не по FPS нативной версии на RTX 4060.
