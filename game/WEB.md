# Web First

Браузер — основная целевая платформа игры. Godot 4.6, GDScript, Compatibility / WebGL 2, однопоточный Web Export без нативных расширений. Эти настройки соответствуют [документации Godot 4.6](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_web.html).

## Текущий статус

Preset `Web` в `export_presets.cfg` успешно собран официальными шаблонами 4.6.stable и запущен во встроенном браузере Codex на компьютере. Проверены оба персонажа и текстуры, клавиатура, автопрыжок, пауза/продолжение, падение, повторная попытка и возврат в меню. Ошибок и предупреждений в доступной консоли при прогоне нет. Исправлены отсутствующие символы стрелок и контраст кнопок.

`Играть в браузере.cmd` запускает скрытый локальный Node.js сервер и открывает http://127.0.0.1:4174/ . Повторный запуск использует уже работающий сервер. `Играть.cmd` запускает нативную игру, а `Запустить сайт.cmd` и порт 4173 — прежний просмотрщик Three.js, не игру.

Ограничения первого браузерного прогона: в окне 390×844 сохраняется горизонтальная компоновка с чёрными полями; требуется отдельная мобильная адаптация. Физический телефон, сенсорный ввод, Safari/Firefox, разрушение камня и работа при отключённом интернете в браузере пока не проверены. Нативные проверки камня не считаются Web проверкой. Сборка без сжатия HTTP занимает около 82 МБ; производительность на слабых устройствах не измерена.

## Подготовка локальной сборки

Понадобятся официальные Export Templates **4.6.stable**, соответствующие установленному движку (Editor → Manage Export Templates). После первоначальной установки сборка не должна требовать интернет. Шаблоны не хранить в Git.

Из корня репозитория, PowerShell:

```powershell
New-Item -ItemType Directory -Force build/web | Out-Null
& '.tools/godot/Godot_v4.6-stable_win64_console.exe' --headless --path game --export-release Web ../build/web/index.html
```

Результат — папка `build/web/`, исключённая из Git. Не переименовывать отдельные файлы экспорта. Для браузера требуется HTTP, не открытие index.html через file://. Сервер `server-game.mjs` обслуживает только build/web на 127.0.0.1:4174 и отдаёт `.wasm` как `application/wasm`. Запуск без открытия вкладки: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./start-web-game.ps1 -NoBrowser`. Журналы — .local/web-game*.log. Старый server.mjs обслуживает Three.js. Публикация не разрешена.

## Проверка при добавлении системы

1. Собрать Web без ошибок; открыть через локальный HTTP в браузере с WebGL 2.
2. Проверить обе модели и текстуры, начало игры, управление, камень, падение, повтор, паузу и возврат в меню; проверить изменённую систему отдельно.
3. Проверить изменение размера окна, узкий экран, сенсорный ввод и возврат фокуса. Эмуляцию не выдавать за тест на физическом телефоне.
4. Проверить ошибки браузера, отсутствие внешних запросов и продолжение работы при отключённом интернете, пока локальный сервер работает.
5. Записать браузер, результат и ограничения в `ПРОВЕРКА.md`; обновить статус здесь и в AGENTS.md после первого успешного прогона.

## Ограничения архитектуры

Не использовать desktop-only API в обязательном игровом пути. Для платформенных функций нужен Web вариант с тем же поведением или явно допустимой деградацией. Сохранения в user:// зависят от доступности браузерного хранилища; отказ не должен ломать игру. Звук и fullscreen запускать после пользовательского действия. Не добавлять обязательные потоки или SharedArrayBuffer; для текущего однопоточного preset они не нужны.

Графическая самопроверка `--self-test` — инструмент для нативного запуска: она сохраняет снимки рядом с проектом. Её результат не заменяет браузерную проверку. Бюджет производительности оценивать в браузере, а не по FPS нативной версии на RTX 4060.
